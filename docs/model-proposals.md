# Natural-language drafts and approvals

The optional hosted model can draft one reminder, simulated calendar event or real Google event, or request a bounded Google calendar read from an ordinary request. It can ask a clarification instead when the date, time, timezone, duration or instruction is missing or ambiguous. The server supplies the accepted message's stable time, account-selected reminder timezone and a nonsecret Google connection flag. A draft is never permission to execute.

The Responses request exposes three strict draft functions and one read-only Google calendar query, with parallel calls disabled. Real Google requests require an explicit active connection; an ordinary real-calendar request is never silently converted into a simulation. The adapter rejects unknown functions, multiple calls, oversized or malformed JSON, extra arguments, invalid dates and unknown UTC offsets. No memory mutation, search request, arbitrary endpoint, email or purchase executor is available to the model. Saved facts and retrieved text remain data rather than authorization.

The server replaces any accompanying model text with its own complete review: exact instruction and schedule, or title/start/duration, explicit real or simulated target, opaque approval ID, ten-minute expiry and confirmation command. Nothing is created at this stage. Send `approve approval_UUID`/`reject approval_UUID` for local reminder/demo proposals or `approve gapproval_UUID`/`reject gapproval_UUID` for real Google proposals, with the exact displayed ID. A bare `yes` does not consume permission. Changing details requires a new proposal.

Approval records bind the account, originating conversation, immutable canonical arguments/digest and relevant settings, context and connection revisions. The server validates them again at commit. A memory/privacy change, notification change, connection revocation or conflicting action revision invalidates stale model drafts. A reminder approval explicitly enables account-wide reminder notifications; quiet hours continue to apply. A read-only Google query returns at most 20 events over at most 31 days, as untrusted data, without another automatic model call or any write. Local calendar proposals remain simulated; real Google proposals are separately labeled and require an active scoped grant. Google updates also require an exact managed event ID and strong ETag, through the explicit command flow.

Local reminder/demo approvals and replies commit with the inbox/outbox transaction under current lease and ownership fences. Google requests use a separate source-unique durable request/cache record; a natural request must exactly match the validated encrypted model result for that same user/source/context. Retries recover the saved review or read result rather than executing again. If approval materialization fails, deterministic fallback text replaces the review. Encrypted model recovery preserves a validated draft across a crash without another paid generation. The user can inspect and reject proposals in the secondary account controls.

Exact command syntax remains available without a hosted key. For example, `remind me in 5 minutes: call Alex` is a complete explicit creation command. An ordinary request such as `Remind me to call Alex tomorrow morning` goes through draft/clarification when hosted AI is configured. Multiline or malformed explicit controls fail closed. Only explicit user commands can save or mutate memory.

Fixtures verify parsing, cache recovery, publication fences, immutable reviews, approval expiry/scope/replay, and one-time task execution. Real model interpretation and usefulness still need a configured provider and live evaluation. The default local configuration is a deterministic mock and does not infer natural-language actions.
